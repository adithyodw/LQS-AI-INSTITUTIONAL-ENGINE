1. EXECUTIVE SUMMARY
================================================================================

LQS Institutional Flow Engine is a quantitative trading system designed to
identify and exploit institutional liquidity events in the XAUUSD (Gold)
market. The system operates on the H1 timeframe and uses a proprietary
five-module signal fusion architecture to filter for high-probability
reversal setups.

The core thesis: institutional participants create liquidity sweeps at key
price levels to fill large orders. By detecting these events and confirming
them through multiple independent analysis methods, the system identifies
entries where the risk-reward profile is statistically favorable.

Key Characteristics:
- Multi-module confirmation reduces false signals
- Institutional-grade risk management with Kelly Criterion sizing
- Adaptive to four distinct market regimes
- No curve-fitting: robust across market conditions
- No DLL, no external API, fully self-contained

3. MODULE A — LIQUIDITY SWEEP DETECTION
================================================================================

Purpose: Identify institutional stop hunts and liquidity grabs at key
price levels where retail stop-loss orders cluster.

3.1 Liquidity Level Sources
────────────────────────────
The system builds a dynamic map of liquidity levels from:

  PDH / PDL     Previous Day High and Low (daily timeframe)
  ASH / ASL     Asian Session High and Low (configurable hours)
  DO            Daily Open price
  LO / NYO      London Open and New York Open prices
  SWH / SWL     Swing High and Low pivots (5-bar pivot detection)
  RND           Round number levels (configurable step, default 50)

Levels are rebuilt every bar. Duplicate levels within 0.5 ATR are merged
to prevent signal clustering.

3.2 Sweep Detection Logic
─────────────────────────
For each active liquidity level, the system evaluates whether a sweep
occurred on the most recent completed bar:

  HIGH Sweep (bearish setup):
  - Price must pierce above the level (H[0] > level)
  - Upper wick must exceed InpSweepWickPct percent of range
  - Volume must exceed InpSweepVolMult times average
  - Sweep depth must exceed InpSweepDepthMin (% of price)
  - Reversal strength must exceed InpSweepRetracePct

  LOW Sweep (bullish setup):
  - Price must pierce below the level (L[0] < level)
  - Lower wick must exceed InpSweepWickPct percent of range
  - Same volume, depth, and reversal requirements

3.3 Sweep Scoring Formula
─────────────────────────
  Score = min(wickPct * 0.35, 35)
        + min((volRatio - 1.0) * 12, 24)
        + min(reversalStr * 0.25, 25)
        + min(depthRatio / 0.001 * 0.5, 10)
        + 6.0 (base)

  Maximum: 100. Multi-sweep bonus: +10 if 2+ levels swept within
  InpMultiSweepBars bars.

3.4 Key Parameters
──────────────────
  InpUsePrevDayHL     Enable Previous Day H/L levels
  InpUseRoundNums     Enable round number levels
  InpRoundStep        Round number spacing (default: 50)
  InpSweepWickPct     Minimum wick percentage (default: 10)
  InpSweepRetracePct  Minimum reversal strength (default: 40%)
  InpSweepVolMult     Volume multiplier threshold (default: 1.0x)
  InpLiqLookback      Lookback for swing pivots (default: 30 bars)
  InpSweepMaxAge      Maximum sweep age in bars (default: 20)
  InpSweepDepthMin    Minimum sweep depth ratio (default: 0.0005)

4. MODULE B — ORDER FLOW ANALYSIS
================================================================================

Purpose: Approximate institutional order flow using OHLC candle structure
and tick volume to confirm whether a liquidity sweep is followed by
genuine directional intent.

4.1 Synthetic Delta Construction
────────────────────────────────
Since raw tick-by-tick order flow is not available in MT5 backtesting,
the system constructs a synthetic delta from candle structure:

  For each bar:
    bias = (Close - Low) / (High - Low)
    delta = (bias - 0.5) * 2.0 * tickVolume

  Positive delta = net buying pressure
  Negative delta = net selling pressure

4.2 Fast/Slow Pressure Differentiation
──────────────────────────────────────
  Fast Pressure: calculated over the most recent 8 bars
  Slow Pressure: calculated over the full lookback window

  When Fast > Slow: buying is accelerating
  When Fast < Slow: buying is decelerating
  This detects momentum shifts at key levels.

4.3 Divergence Detection
────────────────────────
Compares the last 8 bars vs prior 8 bars:

  Bullish Divergence:
    Price makes lower low BUT synthetic delta is higher
    (Institutions absorbing sell-side liquidity)

  Bearish Divergence:
    Price makes higher high BUT synthetic delta is lower
    (Institutions distributing into buy-side liquidity)

4.4 Absorption Detection
────────────────────────
Identifies bars with high volume but small range (< InpAbsorbMaxMove ATR):
  - Signals that large orders are being absorbed without moving price
  - Key confirmation for sweep reversals

4.5 Exhaustion Detection
────────────────────────
Compares first quarter vs last quarter of lookback window:
  - If early delta and late delta have opposite signs, exhaustion = 80
  - Otherwise exhaustion = 30

4.6 Scoring Formula
───────────────────
  Score = divergenceBonus (35 if div found, 15 base)
        + absorptionScore * 0.25
        + exhaustionScore * 0.20
        + min((imbalance - 1.0) * 15, 20)
        + min(abs(deltaMomentum) * 3.0, 10)

4.7 Key Parameters
──────────────────
  InpDeltaLookback    Analysis window (default: 40 bars)
  InpDivergThresh     Divergence sensitivity (default: 8%)
  InpAbsorbBars       Absorption check window (default: 3 bars)
  InpAbsorbVolMult    Volume multiplier for absorption (default: 1.2x)
  InpAbsorbMaxMove    Max range for absorption (default: 0.6 ATR)

5. MODULE C — AMD WYCKOFF CYCLE
================================================================================

Purpose: Classify the market's current phase in the Wyckoff
Accumulation-Manipulation-Distribution cycle on the higher timeframe
to provide structural context for entries.

5.1 Operating Timeframe
──────────────────────
Module C operates on the Higher Timeframe (HTF), configurable:
  InpHTF_Input = 0: H4 (default)
  InpHTF_Input = 1: D1
  InpHTF_Input = 2: W1

5.2 Phase Detection
───────────────────
  ACCUMULATION: Range ratio <= InpAccumRangeRatio AND bullish CO pressure
  MANIPULATION: Manipulation score >= 40 (high volume level breaks)
  MARKUP:       Bullish CO pressure > 60% AND close above range midpoint
  MARKDOWN:     Bearish CO pressure > 60% AND close below range midpoint

Phase transitions require InpPhaseDurMin bars of persistence to prevent
rapid oscillation between phases.

5.3 Spring and Upthrust Detection
─────────────────────────────────
  Spring: Price dips below range low by InpSpringMult * 0.3 * ATR
          then closes back inside range (bullish reversal signal)

  Upthrust: Price pushes above range high by InpUpthrustMult * 0.3 * ATR
            then closes back inside range (bearish reversal signal)

5.4 Volume Climax Detection
───────────────────────────
Flags when any of the last 5 bars has volume >= 1.3x the InpManipVolMult
threshold. Volume climaxes often mark the end of manipulation phases.

5.5 Close-Only (CO) Pressure
────────────────────────────
Measures directional bias by analyzing close position within each bar:
  Bullish: close in upper 45% of range, weighted by volume ratio
  Bearish: close in lower 45% of range, weighted by volume ratio

5.6 Manipulation End Detection
─────────────────────────────
  endManip = true when:
    - Current phase is MANIPULATION
    - Either: (manipulation was bearish AND bullish divergence detected)
              OR (manipulation was bullish AND bearish divergence detected)
              OR absorption score >= 40
    - AND an active sweep exists

5.7 Scoring Formula
───────────────────
  Base: MANIPULATION = 50, ACCUMULATION = 30, MARKUP/MARKDOWN = 25
  Bonuses: endManip +25, spring/upthrust +15, active sweep +10
  Maximum: 100

5.8 Key Parameters
──────────────────
  InpAccumLookback    Range calculation window (default: 20 bars)
  InpAccumRangeRatio  Max range/ATR ratio for accumulation (default: 10)
  InpSpringMult       Spring depth multiplier (default: 0.5)
  InpUpthrustMult     Upthrust depth multiplier (default: 0.5)
  InpManipVolMult     Manipulation volume threshold (default: 1.1x)
  InpCOPressMin       Minimum CO pressure for accumulation (default: 40%)
  InpADLPeriod        Accumulation/Distribution Line period (default: 15)
  InpPhaseDurMin      Min bars to confirm phase transition (default: 1)

6. MODULE D — ANCHORED VWAP SYSTEM
================================================================================

Purpose: Calculate Volume Weighted Average Price from multiple institutional
anchor points to determine fair value, premium/discount zones, and
confluence with liquidity levels.

6.1 Anchor Points (7 Total)
──────────────────────────
  VA_ASIAN     Asian session close (after InpAsianEnd hour)
  VA_LONDON    London session open (InpLondonHour)
  VA_NY        New York session open (InpNYHour)
  VA_WEEK      Weekly open (Monday 00:00)
  VA_DAY       Daily open
  VA_SWING     Most recent swing pivot point
  VA_POC       Anchored to Volume Profile Point of Control

Each anchor is independently configurable (InpVWAP_Asian, etc.).

6.2 VWAP Calculation
───────────────────
For each anchor point i, on each new bar:

  Typical Price (TP) = (High + Low + Close) / 3
  PV[i] += TP * Volume
  V[i]  += Volume
  PV2[i]+= TP^2 * Volume

  VWAP[i] = PV[i] / V[i]
  Variance = PV2[i]/V[i] - VWAP^2
  Sigma = sqrt(Variance)

  Upper SD1 = VWAP + Sigma
  Lower SD1 = VWAP - Sigma
  Upper SD2 = VWAP + 2*Sigma
  Lower SD2 = VWAP - 2*Sigma

6.3 Premium/Discount Zone Classification
─────────────────────────────────────────
  DevSigma = (CurrentPrice - VWAP) / Sigma

  Premium Zone:  DevSigma > +1.0 (price extended above fair value)
  Discount Zone: DevSigma < -1.0 (price extended below fair value)
  Fair Value:    -1.0 <= DevSigma <= +1.0

The direction module uses these zones: discount favors long, premium
favors short. Multi-VWAP alignment (price above/below majority of
active VWAPs) provides additional directional confirmation.

6.4 VWAP Cluster Detection
─────────────────────────
When 2+ VWAPs converge within InpVWAP_ClsDist * ATR, a cluster is
identified. VWAP clusters act as strong support/resistance zones.

6.5 Level Alignment
──────────────────
Checks if any active VWAP is within InpVWAP_LevelTol * ATR of the
sweep level, providing confluence between Module A and Module D.

6.6 Scoring Formula
───────────────────
  Base: 20 (if any VWAP active)
  + 35 if VWAP aligned with sweep level
  + 25 if VWAP cluster detected (>= InpVWAP_ClsMin VWAPs)
  + 20 if deviation score >= 50
  Maximum: 100

6.7 Key Parameters
──────────────────
  InpVWAP_Asian/London/NY/Week/Day/Swing/POC  Enable each anchor
  InpVWAP_MaxBars     Maximum bars per VWAP (default: 300)
  InpVWAP_ClsDist     Cluster distance in ATR (default: 1.5)
  InpVWAP_ClsMin      Minimum VWAPs for cluster (default: 2)
  InpVWAP_DevThresh   Deviation threshold in sigma (default: 1.5)
  InpVWAP_LevelTol    Level alignment tolerance (default: 1.0 ATR)

7. MODULE E — VOLUME PROFILE ANALYSIS
================================================================================

Purpose: Build a simplified Volume Profile to identify institutional
support/resistance zones based on volume distribution.

7.1 Profile Construction
────────────────────────
The system divides the price range of the last InpVP_RollingLen bars into
InpVP_Buckets price buckets and distributes tick volume across them using
the midpoint of each bar's range.

7.2 Key Levels
─────────────
  POC (Point of Control): Price bucket with highest volume
  VAH (Value Area High):  Upper bound of the 70% value area
  VAL (Value Area Low):   Lower bound of the 70% value area
  HVN (High Volume Nodes): Buckets exceeding InpVP_HVN_Pct of maximum
  LVN (Low Volume Nodes):  Buckets below InpVP_LVN_Pct of maximum

7.3 POC Migration
────────────────
Tracks whether POC is migrating up or down between profile updates:
  +1 = POC moving higher (bullish institutional interest)
  -1 = POC moving lower (bearish institutional interest)
   0 = POC stable

7.4 Sweep Confluence
───────────────────
When a sweep is active, Module E checks:
  - POC near sweep level (within InpVP_POC_Tol ATR)
  - VAH/VAL near sweep level (within InpVP_VAL_Tol ATR)
  - LVN beyond sweep level (low volume = fast price movement zone)
  - HVN at sweep level (high volume = absorption zone)

7.5 Scoring Formula
───────────────────
  Base: 25 (even without sweep for market structure context)
  + 25 if VAH/VAL near sweep level
  + 20 if POC near sweep level
  + 15 if LVN beyond sweep level
  + 15 if HVN absorption volume > 3% at sweep level
  Maximum: 100

7.6 Key Parameters
──────────────────
  InpVP_Buckets       Number of price buckets (default: 60)
  InpVP_RollingLen    Profile lookback period (default: 40 bars)
  InpVP_HVN_Pct       HVN threshold percentage (default: 70%)
  InpVP_LVN_Pct       LVN threshold percentage (default: 30%)
  InpVP_POC_Tol       POC-to-sweep tolerance (default: 1.0 ATR)
  InpVP_VAL_Tol       VA-to-sweep tolerance (default: 1.0 ATR)

8. SIGNAL FUSION ENGINE
================================================================================

Purpose: Combine the five independent module scores into a single
confidence-weighted signal with directional consensus.

8.1 Weighted Score Calculation
─────────────────────────────
  Raw Score = wA*ScoreA + wB*ScoreB + wC*ScoreC + wD*ScoreD + wE*ScoreE

Default weights (normalized to 100%):
  Module A (Liquidity Sweep): 35%
  Module B (Order Flow):      20%
  Module C (AMD Wyckoff):     20%
  Module D (Anchored VWAP):   15%
  Module E (Volume Profile):  10%

8.2 Regime-Adaptive Weights
──────────────────────────
Weights shift based on the current market regime:
  STRONG TREND: Module C +20%, Module A +10%
  HIGH VOLATILITY: Module A +40%, Module B +20%
  RANGE: Module B +20%, Module D +20%, Module E +10%
  WEAK TREND: No adjustment

8.3 Directional Consensus
────────────────────────
Each qualifying module casts a directional vote (LONG or SHORT).
Consensus requires:
  - 2+ votes for the same direction
  - Long votes must exceed short votes (or vice versa)

8.4 EMA 50/200 Trend Filter
───────────────────────────
When enabled (InpUseTrendFilter = true):
  - Long entries blocked when EMA50 < EMA200
  - Short entries blocked when EMA50 > EMA200
  This prevents counter-trend entries on the primary timeframe.

8.5 Entry Validation Requirements
─────────────────────────────────
All conditions must be TRUE for a valid signal:
  1. Raw score >= InpScoreEntry (default: 50)
  2. Directional consensus achieved
  3. Module count >= InpMinModules (default: 3 of 5)
  4. Module A (Sweep) must be active (mandatory)
  5. Trend filter passes (if enabled)

8.6 Key Parameters
──────────────────
  InpScoreEntry       Minimum score threshold (default: 45)
  InpMinModules       Minimum confirming modules (default: 2)
  InpModuleMinScore   Min score per module to qualify (default: 20)
  InpWt_A through E   Module weights (default: 40/20/20/10/10)
  InpUseTrendFilter   Enable EMA trend filter (default: true)
  InpAdaptWeights     Enable adaptive weight learning (default: false)

9. RISK MANAGEMENT FRAMEWORK
================================================================================

9.1 Kelly Criterion Position Sizing
───────────────────────────────────
The system uses a fractional Kelly Criterion to size positions:

  b = Average Win / Average Loss
  p = Win Rate
  Kelly = (b * p - (1 - p)) / b
  Position Risk = Kelly * InpKellyFrac (default: 0.25)

  Bounded by: InpRiskMin (0.25%) to InpRiskMax (2.0%)

  Lot = (Equity * PositionRisk) / (SL_Distance / TickSize * TickValue)

9.2 Stop Loss Placement
──────────────────────
Base SL: InpSL_ATR * ATR from entry (default: 2.5 ATR)

If sweep is active: SL placed beyond the sweep extreme:
  Long:  SL = min(sweep_low, entry) - SL_ATR * ATR
  Short: SL = max(sweep_high, entry) + SL_ATR * ATR

HVN adjustment: If a High Volume Node exists beyond the base SL,
the SL is extended to the HVN minus 0.3 ATR (places SL behind support).

9.3 Three-Tier Take Profit
─────────────────────────
  TP1: InpTP1_ATR * ATR (default: 1.5 ATR) — Close InpTP1_Pct (33%)
  TP2: InpTP2_ATR * ATR (default: 3.0 ATR) — Close InpTP2_Pct (33%)
  TP3: InpTP3_ATR * ATR (default: 5.0 ATR) — Remaining position

9.4 Breakeven
────────────
When price reaches InpBE_RMult * SL distance in profit:
  Stop loss moves to entry + 2 points (slight positive offset)

9.5 Trailing Stop
────────────────
After breakeven is set, when price reaches InpTrailStart * SL distance:
  Trail SL = Current Price - InpTrailATR * ATR (for long)
  Trail SL = Current Price + InpTrailATR * ATR (for short)
  Only moves in favorable direction (ratchet mechanism).

VWAP cluster trailing: If a VWAP cluster forms against the position
after breakeven, a tighter trailing stop engages (0.5 ATR).

9.6 Circuit Breakers
───────────────────
  Daily Loss Limit:   Close all + lock if daily P/L <= -InpDailyLossLim%
  Daily Profit Lock:  Close all + lock if daily P/L >= +InpDailyProfLock%
  Equity DD Protect:  Close all + lock if peak equity drawdown >= InpMaxDDPct%
  Max Daily Trades:   Block new entries after InpMaxDailyTrades reached
  Spread Filter:      Block entries when spread > InpMaxSpread points
  Trade Cooldown:     Block entries for InpCooldownBars after last close

9.7 Key Parameters
──────────────────
  InpKellyFrac        Kelly fraction (default: 0.25)
  InpRiskMax          Maximum risk per trade (default: 2.0%)
  InpRiskMin          Minimum risk per trade (default: 0.25%)
  InpSL_ATR           Stop loss in ATR (default: 2.0)
  InpTP1/2/3_ATR      Take profit levels (default: 1.5/3.0/5.0)
  InpTP1/2_Pct        Partial close percentages (default: 33/33)
  InpDailyLossLim     Daily loss limit (default: 5%)
  InpDailyProfLock    Daily profit lock (default: 10%)
  InpMaxDDPct         Peak equity DD limit (default: 8%)
  InpMaxOpen          Maximum open positions (default: 1)
  InpMaxDailyTrades   Maximum trades per day (default: 5)
  InpCooldownBars     Bars between trades (default: 3)

10.1 Fill Type Auto-Detection
────────────────────────────

10.2 Order Retry Logic
─────────────────────

  - Refresh symbol rates
  - Retry up to 3 times
  - 200ms delay between retries
  - Fresh price used on each retry

10.3 Slippage Protection
───────────────────────
Maximum allowed slippage: InpSlippage points (default: 10)

11. MARKET REGIME CLASSIFICATION
================================================================================

The system classifies the current market into four regimes:

  STRONG TREND: ADX >= InpStrongADX (default: 35)
  WEAK TREND:   ADX >= InpTrendADX (default: 20) but < StrongADX
  RANGE:        ADX < InpTrendADX and volatility < InpVolPctile
  HIGH VOLATILITY: Current ATR exceeds InpVolPctile percentile
                   of recent ATR values

Regime affects module weight adjustments in the Signal Fusion Engine.
