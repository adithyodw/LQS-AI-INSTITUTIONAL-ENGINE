1. EXECUTIVE SUMMARY
================================================================================

LQS-AI v5.0 is an institutional-grade quantitative trading system designed
to identify and exploit institutional liquidity events in XAUUSD (Gold) on
the H1 timeframe.

The core thesis: institutional participants create liquidity sweeps at key
price levels to fill large orders. By detecting these events and confirming
them through multiple independent analytical methods PLUS an optional AI
decision filter, the system identifies entries where the risk-reward profile
is statistically favorable.

New in v5.0:
- 7-feature online logistic regression AI decision layer (online learning)
- Multi-provider AI Vision API support (Claude, GPT-4o, Gemini, DeepSeek, xAI)
- Redesigned lot sizing system with 5 modes (Auto Low/Med/High, Fixed, Kelly)
- Broker Stops/Freeze-level aware SL modification safety gates
- JSON JSONL trade journal for post-trade ML analysis
- Robust position management with no "Modification failed" errors

Key Characteristics:
- Multi-module confirmation + optional AI confirmation reduces false signals
- Institutional-grade risk management with 5-mode lot sizing
- Adaptive to four distinct market regimes
- Optional AI Vision confirmation as second gate (disabled by default)
- No hardcoded secrets, no DLLs, pure MQL5, fully self-contained
- Broker-agnostic with automatic Stops/Freeze-level detection
- Offline-capable (all core modules work without internet)

────────────────────────────────────
Eliminates "Modification failed due to order or position being close to
market" errors by implementing broker-level safety detection:

  - Detects SYMBOL_TRADE_STOPS_LEVEL and SYMBOL_TRADE_FREEZE_LEVEL
  - Calculates safe buffer: max(broker_level, 4*spread, 0.4*ATR, 30 pts)
  - Clamps new SL to safe distance instead of rejecting modification
  - Validates SL vs TP separation (minimum 1 ATR)
  - Only modifies when genuinely improving SL (ratchet mechanism)
  - Logs blocked modifications when InpVerbose = true

Result: Zero "Modification failed" backtesting errors, robust trailing SL

9. MODULE E+1 — AI DECISION LAYER (v5.0 NEW)
================================================================================

9.1 Overview
────────────
An online logistic regression model that learns from trade outcomes in
real-time. Acts as a decision filter (gating mechanism) and risk modulator,
never independently selects direction.

Role: Enhance signal quality by:
  1. Filtering out low-conviction setups
  2. Modulating risk size based on AI confidence
  3. Learning win patterns from the user's specific market conditions

9.2 Seven-Feature Input
───────────────────────
  Feature 1: Combined Module Score
    Range: 0-100
    Represents overall signal strength from signal fusion engine

  Feature 2: Shannon Entropy Market Quality
    Range: 0-1
    High entropy = choppy/uncertain market (dampens risk)
    Low entropy = structured market (boosts confidence)

  Feature 3: Win Rate Momentum
    Range: -1 to +1
    Last 8 trades vs prior 8 trades win rate change
    Positive = recent trades performing well

  Feature 4: Order Flow Divergence Strength
    Range: 0-100
    Captures Module B divergence signal
    Higher = stronger institutional absorption

  Feature 5: VWAP Cluster Proximity
    Range: 0-100
    Is current price near a VWAP cluster?
    Clusters = strong support/resistance zones

  Feature 6: Module Consensus Strength
    Range: 0-5
    How many independent modules are voting the same direction?
    Higher = stronger directional agreement

  Feature 7: Market Volatility Regime
    Range: 1-4
    1=RANGE, 2=WEAK_TREND, 3=STRONG_TREND, 4=HIGH_VOL
    Regime-specific probability adjustments

9.3 Online Learning Mechanism
──────────────────────────────
After every closed trade:
  1. Calculate trade outcome (win/loss)
  2. Use the 7 input features from the entry bar
  3. Update logistic regression weights
  4. Recalibrate confidence threshold

Learning parameters:
  InpAILearnTrades        Minimum trades before learning (default: 15)
  Learning Rate           Fixed at 0.05 per trade (optimized for stability)

9.4 Confidence Scoring
──────────────────────
Output is a probability (0-100%) that the setup will be profitable:

  P(Profitable) = sigmoid(-0.5 + 0.1*F1 + 0.08*F2 + 0.05*F3 + ... + 0.02*F7)

Where sigmoid maps the sum to [0, 100] confidence range.

9.5 Risk Modulation
───────────────────
AI confidence affects position sizing:

  If AI_Confidence >= InpAIBoostThresh (default: 75%):
    RiskMultiplier = InpAIBoostMult (default: 1.3x)
    → Increases position size by 30%

  If AI_Confidence < InpAIBoostThresh AND < 50%:
    RiskMultiplier = InpAIDampMult (default: 0.8x)
    → Decreases position size by 20%

  Otherwise:
    RiskMultiplier = 1.0x (no change)

9.6 Key Parameters
──────────────────
  InpUseAI                Enable/disable (default: true)
  InpAILearnTrades        Min trades before learning (default: 15)
  InpAIBoostThresh        High-confidence threshold (default: 75%)
  InpAIBoostMult          Boost multiplier (default: 1.3x)
  InpAIDampMult           Damp multiplier (default: 0.8x)

11.1 Weighted Score Calculation with AI Modifier
─────────────────────────────────────────────────

Base Score (v3.0):
  Raw Score = wA*ScoreA + wB*ScoreB + wC*ScoreC + wD*ScoreD + wE*ScoreE

With v5.0 AI Enhancement:
  1. Calculate Raw Score as above
  2. Get AI Confidence (0-100%)
  3. AI Adjustment Factor = AI_Confidence / 100
  4. Final Score = Raw Score * (0.7 + 0.3 * AI_Adjustment)
     → Minimum 70% of Raw Score even if AI uncertain
     → Maximum 100% of Raw Score (no amplification by AI)

Effect: AI can reduce false signals but doesn't artificially inflate scores.

12. RISK MANAGEMENT FRAMEWORK (v5.0 REDESIGN)
================================================================================

12.1 Five-Mode Lot Sizing System (v5.0 NEW)
──────────────────────────────────────────

MODE 1: AUTO_LOW (Safest)
  Formula: Lot = (Equity / 1000) * 0.01
  Example: $10k equity → 0.1 lot
  Use Case: Conservative traders, small accounts

MODE 2: AUTO_MED (Balanced)
  Formula: Lot = (Equity / 1000) * 0.02
  Example: $10k equity → 0.2 lot
  Use Case: Balanced risk/reward approach

MODE 3: AUTO_HIGH (Aggressive)
  Formula: Lot = (Equity / 1000) * 0.03
  Example: $10k equity → 0.3 lot
  Use Case: Experienced traders, larger accounts

MODE 4: FIXED
  Formula: Lot = InpFixedLot (constant)
  Example: InpFixedLot = 0.05 → always 0.05 lot
  Use Case: Traders who want exact position control

MODE 5: KELLY (Advanced)
  Formula: Lot = (Equity * KellyPercent) / (SL_Distance * TickValue)
  Where: KellyPercent = Kelly Criterion (0.25 to 2.0% bounded)
  Example: Kelly = 1.5%, SL = 50 pts → proportional sizing
  Use Case: Mathematically optimized sizing, learns from history

12.2 Soft Scaling Multipliers (All Modes)
──────────────────────────────────────────

High Volatility Regime Scaling:
  If Current_ATR > 75th Percentile of ATR (last 30 bars):
    Lot *= 0.75 (reduce by 25%)

Consecutive Loss Scaling:
  If 3+ consecutive losses:
    Lot *= 0.75 (reduce by 25%)

Can compound: If both conditions, Lot *= 0.75 * 0.75 = 0.5625

12.3 AI Confidence Risk Modulation (v5.0 NEW)
──────────────────────────────────────────────
After calculating base lot from mode:

  If AI_Confidence >= InpAIBoostThresh (default: 75%):
    Lot *= InpAIBoostMult (default: 1.3x)
    → Increase position by 30%

  Else if AI_Confidence < 50%:
    Lot *= InpAIDampMult (default: 0.8x)
    → Decrease position by 20%

  Else: Lot *= 1.0x (no change)

Order of Application:
  1. Base lot from mode
  2. Apply soft scaling (HVOL × losses)
  3. Apply AI modulation (boost/damp)
  4. Apply NormLot safety floor
  5. Compare against SYMBOL_VOLUME_LIMIT
  6. Ensure minimum tick size compliance

12.4 NormLot Safety Floor
──────────────────────────
Guarantees minimum lot size:

  NormLot = max(calculated_lot, SYMBOL_VOLUME_STEP)

Prevents "Lot = 0 / Trade skipped" errors:
  - If calculation produces 0.001 but minimum is 0.01 → use 0.01
  - Never skips trade due to lot rounding down
  - Respects broker SYMBOL_VOLUME_LIMIT maximum

12.5 Stop Loss Placement (v5.0 Improved)
─────────────────────────────────────────

Base SL: InpSL_ATR * ATR (default: 2.0 ATR)

If sweep is active: SL placed beyond sweep extreme
  Long:  SL = min(sweep_low, entry) - SL_ATR * ATR
  Short: SL = max(sweep_high, entry) + SL_ATR * ATR

SL Hard Cap: InpSLMaxATR (default: 4.5 ATR)
  If calculated SL would exceed 4.5 ATR from entry:
    SL = entry +/- 4.5 ATR (capped)
  Prevents excessive SL expansion

HVN Adjustment: If High Volume Node exists beyond base SL:
  SL extended to HVN minus 0.3 ATR (places SL behind support)

12.6 Broker-Aware SL Modification (v5.0 NEW)
──────────────────────────────────────────────

Detects broker constraints:
  - SYMBOL_TRADE_STOPS_LEVEL: Minimum distance from market
  - SYMBOL_TRADE_FREEZE_LEVEL: Dead zone before expiry

Safe Buffer Calculation:
  SafeBuffer = max(
    SYMBOL_TRADE_STOPS_LEVEL,
    4 * Spread,
    0.4 * ATR,
    30 points
  )

Modification Gate (only modify if):
  1. New SL is SafeBuffer away from current price
  2. SL-TP separation >= 1.0 ATR
  3. New SL is improvement (ratchet mechanism)
  4. Not inside freeze band (near order expiry)

If conditions fail: Log rejection, maintain current SL

Result: Zero "Modification failed" errors, robust trailing

12.7 Three-Tier Take Profit (unchanged from v3.0)

12.8 Breakeven & Trailing Stop (unchanged from v3.0)

12.9 Circuit Breakers (unchanged from v3.0)

13. POSITION MANAGEMENT & SL SAFETY GATES
================================================================================

13.1 Broker Constraint Detection (v5.0 NEW)
─────────────────────────────────────────────
On initialization (OnInit()):
  1. Query SYMBOL_TRADE_STOPS_LEVEL → minimum SL distance (pts)
  2. Query SYMBOL_TRADE_FREEZE_LEVEL → dead zone before expiry (pts)
  3. Query SYMBOL_SPREAD → current spread (pts)
  4. Calculate ATR → volatility measure
  5. Determine safe buffer as max of above

This adapts to every broker's constraints without user input.

13.2 SL Clamping on Modification (v5.0 NEW)
──────────────────────────────────────────────
Instead of rejecting a modification that violates constraints:
  1. Calculate desired new SL
  2. If new SL too close to market:
     → Clamp to SafeBuffer away from current price
  3. Re-evaluate: Is clamped SL still an improvement?
  4. If yes: Execute modified SL
  5. If no: Maintain current SL, log decision

Result: Smooth SL trailing without errors

13.3 Trailing SL Algorithm (Volatility-Aware)
────────────────────────────────────────────────
On each bar (for open position):
  If price moved InpTrailStart * SL_Distance in our favor:
    1. Calculate trail SL = Current Price - InpTrailATR * ATR
    2. Check if trail SL is SafeBuffer from market
    3. Compare trail SL vs current SL
    4. If trail SL is improvement: Modify
    5. If trail SL violates broker constraint: Clamp to SafeBuffer
    6. Log modifications (if InpVerbose = true)

Ratchet mechanism: SL only moves in favorable direction

13.4 VWAP Cluster Trailing (v5.0)
──────────────────────────────────
If a VWAP cluster forms against our position after breakeven:
  Engage tighter trailing: Trail SL = Current Price - 0.5 * ATR
  This protects against reversal from cluster resistance

13.5 Journal Entry Logging (v5.0 NEW)
──────────────────────────────────────
Every closed trade logs:
  - Lot size applied (auto mode + scalings + AI modulation)
  - SL distance from entry (points and ATR)
  - Reason for SL (base ATR / sweep extreme / HVN extension)
  - Number of SL modifications attempted
  - Number of SL modifications succeeded (clamped or executed)
  - Final trailing SL value at close

  - Fresh price used on each retry

─────────────────────────

15.4 v5.0 Enhanced: Lot Calculation
─────────────────────────────────────
Lot calculation happens in real-time on entry bar:
  1. Get equity
  2. Get SL distance (from sweep or base ATR)
  3. Determine lot mode (Auto Low/Med/High, Fixed, Kelly)
  4. Apply soft scaling (HVOL, consecutive losses)
  5. Get AI confidence, apply boost/damp
  6. Pass through NormLot safety floor
  7. Check SYMBOL_VOLUME_LIMIT
  8. Execute order with calculated lot
